# Ostraka

Incident management and response for teams. It is the record of an incident: the people, the work, the decisions and the assessments. It sits beside Rowanholt (evidence and analysis) and Shikari (detection and hunting) and doesn't duplicate either. The plan and every product decision are in `docs/ROADMAP.md`; read it before starting a phase.

## Layout

- `backend/`: FastAPI, `ostraka` package. `ostraka/api/` routers, `ostraka/models/` SQLAlchemy models, `ostraka/auth/` (passwords and secrets, TOTP, JWTs, sessions, `policy.py` for who may do what, `deps.py` for request identity), `ostraka/accounts.py` (invitations and backup codes, shared with `ostraka/cli.py`), `ostraka/audit.py` (the security log), `ostraka/observables/` IOC detection, `ostraka/branding.py` (the product's name and wording; nothing else hard-codes it), `ostraka/busy.py` (the homelab `/api/busy` contract), `ostraka/incidents/` (access rules, the hash-chained activity log, IOC masking, #references; a record is an incident or a hunt, `Incident.kind`), `ostraka/api/links.py` (links between records and hunt promotion), `ostraka/standard/` (the reporting standard as fixed rules: the PHIA yardstick, the assessment linter and sentences, ACH arithmetic), `ostraka/api/assessments.py`, `ach.py` and `lessons.py` with `ostraka/analysis_schemas.py`, `ostraka/reports/` (`incident.py` says what a report contains, `branded.py` renders blocks to PDF and Word, `charts.py`, `theme.py` the palette in force and a brand's derived one, `brands.py` logo cleaning and an export's styling, bundled fonts and `attack.json`; `api/reports.py` exports), `ostraka/licence.py` (editions from a signed licence; `api/installation.py` licence and brands; `scripts/admin/` signs, off-server; the model shared with Shikari and Rowanholt is `docs/LICENSING_MODEL.md`), `ostraka/live.py` (WebSocket hub over Redis pub/sub), `ostraka/work.py` (task ownership and announcements), `ostraka/workflow.py` (playbook workflows: when a step opens, decisions and their outcomes, hand-offs), `ostraka/notify/` (notifications; push, email and Teams in `channels.py`, Web Push encryption in `push.py`), `ostraka/webhooks.py` (signed webhooks, the `automation` feature, sent from activity after the commit through `notify.outward_data`; `api/webhooks.py` admin only), `ostraka/scheduler.py` (reminders and escalation, one process per tick by advisory lock), `ostraka/mcp_server.py` (MCP at `/mcp`: tools call the API in-process as the token's owner; restricted TLP stays out), `ostraka/importer.py` (`ostraka import`: records loaded through the API, replayed in time order; the sample is `ostraka/samples/sample.json`), `migrations/` (Alembic).
- `frontend/`: React, Vite and TypeScript. `src/api/client.ts` is the only way to call the API, `src/auth/session.ts` holds who is signed in, `src/styles/tokens.css` holds every colour, `src/theme/` the palette and mode choice, `src/brand.ts` mirrors `branding.py`. Server data goes through TanStack Query; `src/live/live.ts` invalidates the sections a live event names. `src/pages/incident/` holds the incident page, one file per section. `src/components/sherd/` is the mark cut into its fragments (`geometry.ts`), animated in `Ostrakon.tsx` and scattered behind the app by `SherdField.tsx`.
- Distribution (phase 3b; the contract is `desktop/README.md`, change it there first): `ostraka` is the host CLI (Bash 3.2-safe; start, stop, status, first-admin, server init, app install, anything else to the backend's CLI), with `desktop/windows/ostraka-cli.ps1` its PowerShell twin. `desktop/` holds the launchers and packagers (`macos/` Swift and `.dmg`, `windows/` `Ostraka.ps1` and the WiX `.msi`, `linux/` the app-mode launcher and `.deb`; no `.rpm`, since `install.sh` installs the source tarball where there's no apt; one universal package per platform, named as Rowanholt's: `Ostraka-<v>-macos-universal.dmg`, `Ostraka-<v>-windows-universal.msi`, `ostraka_<v>-1_all.deb`), `icons/`, `install` and `uninstall` scripts in Bash and PowerShell, and `source-tarball.sh`, the `git archive` every package carries. `clients/` is the responder client, `ost` and `ost.ps1`. `scripts/release.sh` (`make release VERSION=…`) is the local build: every package into `dist/<version>/` with SHA256SUMS and, with `--upload`, a draft GitHub release. A `v*` tag builds the same files on GitHub (`.github/workflows/desktop-release.yml`, Rowanholt's job for job). `deploy/` sets up a team server, named as in Shikari: `deploy/linux/install.sh`, `deploy/windows/install-service.ps1` (under WSL 2), `docker-compose.caddy.yml`; there are no native server packages, since the server is the compose stack. `tests/launcher` tests the host CLI and `tests/install` the install and release scripts (`make test-launcher`, `make test-scripts`).
- `docker-compose.yml`: db, redis, backend, web. Only `web` publishes a port (127.0.0.1:24747).

## Rules

- **Schema changes go through Alembic only.** Nothing calls `create_all`. Each revision must upgrade, downgrade and upgrade again (`tests/test_migrations.py` checks this against Postgres).
- **Colours come from tokens.** Components use `var(--…)` only, never a literal colour. Palettes change colour only: type, spacing and radii are the same in every theme. Severity and TLP colours never change with the palette.
- **No secrets in the repo.** In production, settings refuse a missing, short or placeholder `OSTRAKA_SECRET_KEY`. `make env` writes `.env`.
- **No open registration.** Accounts are created by invitation only. TOTP is mandatory for every account. Permission rules live in `ostraka/auth/policy.py` as pure functions, each with a unit test.
- **Every security-relevant change is recorded** with `audit.record(...)`: sign-ins, invitations, account and MFA changes, tokens.
- **Tokens:** the access token is held in memory, the refresh token in an httpOnly, SameSite=Strict cookie. Nothing goes in `localStorage` except per-browser conveniences such as the theme. The WebSocket authenticates with a short-lived ticket, never a JWT in the query string.
- **The browser talks to one origin.** There's no CORS middleware: nginx in production and Vite's proxy in development serve the API on the page's own origin.
- **The reporting standard is enforced by Ostraka itself, not AI.** Confirmation needs a verification, assessments are stored as structured parts, the linter and ACH arithmetic are deterministic, and probability uses the PHIA yardstick's closed list of terms. AI may only rephrase a finished draft, and a rephrase that drops or changes a claim, citation or probability term is rejected. The TLP guard keeps TLP:RED and TLP:AMBER+STRICT incidents on local Ollama.
- **Leads and confirmed findings stay separate.** Only an analyst confirms a finding, the same rule Rowanholt applies.
- **Live messages say what changed, never the content.** A broadcast reaches every viewer, observers included, so clients refetch through the API, which masks IOCs per viewer.
- **Notifications are written in the transaction and sent after the commit** (`activity.finish` calls `notify.dispatch`). Anything that leaves Ostraka goes through `notify.outward`: indicators masked, and only the reference for TLP:RED and TLP:AMBER+STRICT.
- **Edits carry a version.** A stale one gets 409 and the client fetches the current record; nothing is silently overwritten.
- **Python:** type hints and docstrings on public functions, `pathlib`, f-strings, `get_logger(__name__)` (never `print`). Ruff config is in `pyproject.toml`; line length 110.
- **Tests:** pytest for the backend (`asyncio_mode = auto`, httpx `ASGITransport`), Vitest for frontend units, and Playwright against the production build with the API stubbed through `page.route`. New behaviour comes with a test. `make check` (lint, unit tests, database tests against a throwaway Postgres, and e2e) must pass before a commit.
- **Releases build on GitHub, as Rowanholt's do** (Ben, 11 November 2026, replacing the 10 November rule). `.github/workflows/desktop-release.yml` mirrors Rowanholt's: a `v*` tag (or a manual run) builds the `.dmg`, `.msi` and `.deb`, installs and uninstalls each on its own runner, and a tag attaches them with SHA256SUMS to a draft release. It's the only workflow: `make check` still runs locally before every commit, and there's no CI for it. The repository is private, so macOS and Windows minutes count against the allowance at a multiple; tag a release, don't loop manual runs.
- **No new dependency** without saying why in the commit message.
- **Scripts keep LF and filenames never clash by case.** `.gitattributes` forces LF on `*.sh`, `ostraka` and `clients/ost`, which run on Linux and macOS even from a Windows checkout; add any new extensionless script there. Never put two files in one folder whose names differ only by case: macOS and Windows disks are case-insensitive, so `Ostraka.ps1` and `ostraka.ps1` were the same file (hence `ostraka-cli.ps1`).
- **British English** throughout: UI copy, docs and comments.
- **The name is Ostraka** wherever people read it: UI copy, messages, reports, documents and the terms (Ben, 11 November 2026). It stays `ostraka` in paths, packages, commands, identifiers, URLs and formats (`ostraka-licence-1`, `ostraka-import/1`); code comments aren't changed for it. The Greek noun *ostraka* (the sherds) stays lower case.

## Hosting

On the homelab: `homelab add ostraka <repo> --port 24747 --upstream 24747 --env <repo>/.env`, then `homelab name ostraka`.
- `homelab-proxy` terminates TLS, so Ostraka needs no restart after a certificate renewal.
- `homelab pull` asks `GET /api/busy` before rebuilding. Register a check in `ostraka/busy.py` for anything a restart would interrupt.

## Decisions

- 10 November 2026:
  - Rebuild rather than refactor; there's no data to migrate.
  - React SPA; plain CSS tokens, no Tailwind.
  - Cobalt is the default theme, with Ostrakon and Ledger available under preferences. Fonts are fixed: Inter and JetBrains Mono.
  - Phases are Detect → Scope → Contain → Eradicate → Recover → Learn.
  - The AI provider can be Ollama or Anthropic, with the TLP guard.
  - Nudges go in-app with browser push, by email, and through Microsoft Teams webhooks.
  - The reporting standard (verified confirmation, defensive writing, an assessment in every update, ACH) is built into Ostraka and doesn't depend on AI.
- 10 November 2026 (phase 1):
  - MFA is mandatory for everyone.
  - The first admin comes from `ostraka bootstrap-admin`.
  - Team leads invite responders and observers into their own team only.
  - Refresh tokens rotate, and replaying an old one revokes its whole family.
  - Cookie endpoints require the `X-Ostraka: 1` header.
  - Read-only (`mcp`) API tokens are refused on any non-GET request.
- 10 November 2026 (distribution): web plus desktop apps for macOS, Windows and Linux, with central and local modes on Rowanholt's pattern; Bash and PowerShell installers, a responder client and server setup; local mode keeps password and TOTP. Built after phase 3, as phase 3b.
- 10 November 2026 (rename): ciphr is now **Ostraka** (CIPHR Ltd's UK marks). References `OST-`, tokens `ost_`, settings `OSTRAKA_*`, header `X-Ostraka`, the Cryptex palette is Ostrakon (migration 0008), and sign-in is the sherd and a split-flap board. Two HKDF labels keep the old name on purpose (`auth/secrets.py`, `notify/push.py`): changing them would orphan stored TOTP secrets and push subscriptions. The brand is in `docs/BRAND.md`, the diagrams in `docs/diagrams/` (`draw.py` redraws them).
- 11 November 2026 (reports): assessments, ACH and lessons learned are built ahead of phase 4, with exports as a full technical report and a shorter briefing in PDF and Word. Every report uses the Ostrakon palette. Anyone who worked on an incident may export; a sensitive incident exports for its commander only.
- 11 November 2026 (editions): Free is 4 people who can sign in, one an admin or team lead, reports in Ostrakon. Pro has the licence's seats and one report brand; Services (MSSPs and consultancies), priced higher, a brand per incident and the right to run Ostraka for clients. Licences are Ed25519-signed and checked offline; the private key is Ben's (`~/.config/ostraka/licence-signing.key`), never in the repo or on a server. A lapsed licence never deactivates anyone. Severity and TLP colours never take a brand's. The code is under the Elastic License 2.0, with `COMMERCIAL-LICENSE.md` for the paid editions (draft, for legal review), as for Shikari and Rowanholt.
- 10 November 2026: Celery is removed. Redis pub/sub carries live updates, and a lightweight in-process scheduler handles nudges.
